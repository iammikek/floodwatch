Design constraints (agreed direction)

  • Lean map — spatial only; avoid dense markers and popup-heavy UX (slow to render/refresh).
  • Detail in panels — select a feature → inspector / corridor / river strips update.
  • Client ownership of the map — Livewire is questionable for this surface; Vue (or Inertia+Vue island) is the preferred spike for scale/performance. Laravel + lake stay the backends.

Screens

  1. 01 Operator cockpit — risk + route, corridor risk strip, map, summary cards, river response. Toggle at risk vs stable.
  2. 02 Map layers — prefer presets over many toggles; keep default layers sparse.
  3. 03 Upstream trends (stub) — near-term product idea; fake series. Not in Blade WIP.
  4. 04 Lean map + inspector — selection → panel; no popovers as primary info.

Review questions

  1. Does corridor risk belong above the map, or should the map lead?
  2. Are flood exposure counts + route verdict redundant with the four summary cards below the map?
  3. Is river response the right depth for dispatch, or should it collapse until elevated?
  4. Layer presets (Dispatch / Hydrology) vs a full checkbox menu?
  5. For trends: same page as cockpit, or a dedicated “outlook” mode?
  6. Spike Vue cockpit island next, or finish HTML wireframe iteration first?
